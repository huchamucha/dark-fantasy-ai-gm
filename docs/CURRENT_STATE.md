# Первичный аудит текущего репозитория

**Проверенная ветка:** main  
**Репозиторий:** huchamucha/dark-fantasy-ai-gm  
**Статус:** обзор по содержимому GitHub; локальный запуск и тесты не выполнялись.

## 1. Что обнаружено

В корне находятся:
- `app.py` и `game_engine.py`, `game_state.py`, `llm_client.py`, `prompts.py` — ранний Flask/text-first контур;
- `backend/app` — отдельный FastAPI backend;
- `frontend` — React + TypeScript + Vite.

README описывает Flask-приложение на порту 5000, тогда как backend FastAPI содержит отдельные маршруты кампаний и ходов. Это два разных entrypoint-а; нужно выяснить, какой из них реально используется в актуальной локальной копии.

## 2. Backend FastAPI — текущее состояние по коду

Есть:
- FastAPI entrypoint;
- маршруты campaigns и turns;
- Pydantic-схемы campaign, character, turn и world;
- GameService, world_service, world_state и llm_service;
- стартовая история с локацией «Подступы к собору», NPC «Брат Эдрик» и квестом «Пепельная Корона».

Ограничения и риски:
- `GameWorldStore` хранит кампании и персонажей в обычных словарях Python: после перезапуска процесса состояние теряется.
- `process_turn` передаёт ответ LLM в `update_after_turn`, а тот применяет hp_change, stat_changes, inventory_changes, quest_updates, npc_updates и world_flags напрямую. Это противоречит целевой архитектуре, где изменения сначала проверяет Game Engine.
- Исходный текст действия игрока попадает в контекст LLM, но не сохраняется в recent_events.
- `turn_id` сейчас фиксирован как `turn_0001`.
- `DEFAULT_FALLBACK` содержит ненулевое изменение характеристики и world flag; при ошибке модели fallback может менять мир без реального игрового действия.
- В системном промпте есть вероятная опечатка латинской буквы в слове «Сохраняй»; это косметический дефект.
- `config.py` в проверенной ветке main использует значения по умолчанию `http://localhost:11434/v1/chat/completions` и `gpt-4o-mini`. Это не совпадает с рабочими локальными настройками, ранее сообщёнными пользователем: LM Studio на порту 1235 и модель `qwen2.5-7b-instruct`. Проверить локальный `.env` и не коммитить секреты.

## 3. Frontend

В `frontend/src` есть App.tsx, api.ts, main.tsx и types.ts. Используется React 18, TypeScript и Vite. По одному лишь перечню файлов нельзя подтвердить полноту интерфейса и его фактическую работоспособность; нужен отдельный просмотр App.tsx и запуск сборки.

## 4. Рекомендуемый порядок исправлений

1. Сверить GitHub main с локальной рабочей копией пользователя.
2. Определить и документировать единственный основной способ запуска (FastAPI или legacy Flask).
3. Добавить тесты на текущий игровой цикл.
4. Разделить ответ LLM на intent/предложение и художественный narrative.
5. Убрать прямое применение механических изменений от LLM; выполнять их только через валидаторы движка.
6. Сохранить player_action и генерировать уникальный turn_id.
7. Заменить in-memory store на SQLite отдельным этапом с миграциями и проверкой сохранений.
8. После стабилизации вынести контент первой истории в Story Pack.

## 5. Ограничения этого аудита

Это первичный статический обзор файлов, доступных в ветке main. Не выполнялись:
- установка зависимостей;
- запуск backend или frontend;
- pytest или frontend build;
- проверка локальной папки пользователя;
- проверка незакоммиченных изменений.

Поэтому документ фиксирует наблюдаемые факты и риски, но не утверждает, что код проходит или не проходит runtime-тесты.
