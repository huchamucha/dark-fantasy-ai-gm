# Аудит и текущее состояние проекта

**Репозиторий:** `huchamucha/dark-fantasy-ai-gm`  
**Основа:** `main` + документационный PR #1  
**Рабочая интеграционная ветка:** `project/complete-current-state`  
**Тип аудита:** статический анализ содержимого GitHub; локальная рабочая папка пользователя не проверялась.

## 1. Общая картина

В репозитории исторически существуют два контура:

1. Корневой Flask-прототип: `app.py`, `game_engine.py`, `game_state.py`, `llm_client.py`, `prompts.py`.
2. Основной контур дальнейшей разработки: `backend/app` (FastAPI) + `frontend` (React/Vite).

В актуальной интеграционной ветке README явно определяет FastAPI + React как основной путь. Flask-прототип сохранён как legacy, поскольку он содержит ранние наработки и не должен удаляться без отдельной миграции.

## 2. Backend — что есть

- FastAPI entrypoint `backend/app/main.py`.
- API кампаний и ходов: `routes/campaigns.py`, `routes/turns.py`.
- Pydantic-схемы кампании, персонажа, хода и снимка мира.
- Сервисы `game_service.py`, `world_service.py`, `world_state.py`, `llm_service.py`.
- Стартовая история: «Пепельная Корона», Подступы к собору, Брат Эдрик, руны и тень под городом.

## 3. Исправления, внесённые в интеграционную ветку

- `backend/app/config.py` загружает `.env` из корня проекта и использует локальные значения LM Studio: порт 1235 и модель `qwen2.5-7b-instruct` по умолчанию.
- Создан `backend/app/prompts/game_master_ru.py` с консолидированным русским системным промптом.
- `backend/app/services/llm_service.py` разбирает JSON и оставляет только narrative-поля; изменения HP, характеристик, инвентаря, квестов и world flags принудительно обнуляются/очищаются.
- Fallback при недоступности модели больше не меняет состояние мира.
- `GameService.process_turn` создаёт уникальный UUID для каждого хода.
- Исходное действие игрока передаётся в хранилище и записывается в recent_events вместе с narrative, summary и event_id.
- `README.md` определяет основной контур и содержит актуальные инструкции запуска Windows.
- `.env.example` описывает переменные FastAPI и отдельно legacy Flask.

## 4. Важная граница: чего движок пока НЕ умеет

Сейчас безопасное поведение достигнуто временным ограничением полномочий LLM: модель только рассказывает историю. Полноценный движок ещё не реализован. Пока нет авторитетного слоя для:

- D20, модификаторов и DC;
- проверок навыков и критических исходов;
- боя, инициативы, урона, брони и статусов;
- валидации применения предмета и проверки владения;
- разрешения квестовых условий и последствий;
- механических изменений NPC и world state.

Это намеренно: лучше пока не менять HP и инвентарь автоматически, чем позволять LLM выдумывать предметы и результаты. Следующий этап — отдельный Game Engine, который будет принимать структурированный intent и проверять его.

## 5. Хранилище

`GameWorldStore` пока хранит кампании и персонажей в словарях Python. Это означает:

- данные теряются после перезапуска backend;
- нет транзакций и устойчивых сохранений;
- нет миграций и резервного копирования;
- отсутствует изоляция по пользователям (мультипользовательский режим сейчас не является целью).

Целевой следующий шаг: SQLite + SQLAlchemy 2 + Alembic. Не внедрять PostgreSQL и Qdrant до появления реальной потребности.

## 6. Frontend — первичный анализ

- React 18, TypeScript, Vite.
- `App.tsx` содержит создание кампании, создание персонажа и отправку хода.
- `vite.config.ts` проксирует `/api` на порт 8000.
- Интерфейс пока прототипный: нет полноценного разделения на экраны и features, журнала, инвентаря, карты, боевого UI и asset pipeline.
- В `App.tsx` ответы fetch не проверяют `response.ok`; часть ошибок может быть показана слишком общо. Это отдельная задача frontend hardening.
- Начальное состояние кампании и некоторые тексты в UI пока жёстко привязаны к тёмному фэнтези.

## 7. Конфигурация и запуск

- LM Studio: `http://localhost:1235/v1`.
- Chat completions URL: `http://localhost:1235/v1/chat/completions`.
- Model ID: `qwen2.5-7b-instruct` (сверить с `/v1/models`).
- FastAPI: порт 8000.
- Vite: порт 5173.
- Локальный `.env` хранится в корне и не коммитится.

Полные команды запуска находятся в корневом README и `docs/DEVELOPMENT_NOTES.md`.

## 8. Legacy-контур

Корневой Flask-код использует отдельные переменные `LMSTUDIO_BASE_URL`, `LMSTUDIO_API_KEY`, `LMSTUDIO_MODEL`, другой формат игрового состояния и собственный `prompts.py`. Он не синхронизирован автоматически с новым FastAPI-промптом. В дальнейшем нужно либо перенести нужные функции в основной контур, либо явно заморозить legacy. Не запускать оба backend на одном порту.

Также `backend/app/llm_service.py` — старый дублирующий модуль. Активный сервис, используемый GameService, находится в `backend/app/services/llm_service.py`. Дубликат требует последующей чистки после проверки импортов.

## 10. Что не проверено

Через GitHub удалось прочитать и изменить исходники, но не запустить их в пользовательском окружении. Не выполнялись:

- установка Python/npm зависимостей;
- `python -m compileall` или `pytest`;
- запуск FastAPI и проверка Swagger;
- `npm run build`;
- реальный запрос к LM Studio;
- проверка локальных незакоммиченных файлов пользователя.

Поэтому текущая ветка — интеграционная сборка с внесёнными изменениями, но не подтверждённый локальными тестами релиз. Перед использованием заменить локальную копию безопасным переключением ветки/резервной копией и выполнить smoke tests.
