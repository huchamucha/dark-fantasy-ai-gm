# План реализации

- [x] Зафиксирована целевая архитектура и технические решения.
- [x] Проведён статический аудит GitHub-версии репозитория.
- [x] FastAPI + React/Vite определены основным контуром; Flask сохранён как legacy.
- [x] LM Studio config и загрузка корневого `.env` приведены к локальному профилю.
- [x] Консолидированы правила ведущего: конкретика, контроль игрока, развитие сцены, согласованность NPC.
- [x] LLM ограничена повествованием; механические изменения из ответа отбрасываются.
- [x] Действие игрока сохраняется в recent_events, turn_id/event_id уникальны.
- [x] Добавлены базовые unit-тесты парсера и защиты от state mutation.
- [ ] Проверить запуск, Python tests и frontend build локально.

## Этап 0. Аудит и базовая версия
- Сверить локальную папку с GitHub-веткой.
- Проверить запуск FastAPI и frontend.
- Выполнить тесты и smoke tests.
**Готово, когда:** воспроизводимый запуск и достоверная карта кода.

## Этап 1. Стабилизация игрового цикла
- [x] Отделить повествование LLM от механических изменений состояния.
- [x] Нормализовать ответ LLM и очищать HP/stat/inventory/quest/world mutations.
- [x] Сделать fallback нейтральным.
- [x] Сохранять исходное действие игрока в журнале.
- [x] Генерировать уникальные turn_id и event_id.
- [x] Добавить тесты фильтрации изменений (ожидают локального запуска).
- [ ] Ввести intent schema и отдельную валидацию допустимости действия.
- [ ] Реализовать игровые проверки и применять изменения только после движка.
**Готово, когда:** AI не может самовольно выдать предмет, изменить характеристики или объявить успех без проверки движком.

## Этап 2. Story Pack loader
- Добавить каталог story_packs и manifest schema.
- Реализовать поиск и валидацию пакетов.
- Перенести «Пепельную Корону» в story_packs/dark_fantasy.
**Готово, когда:** история загружается из пакета, а не из универсального сервиса.

## Этап 3. Доменные модели и хранение
- Определить Story, Campaign, Character, NPC, Location, Item, Inventory, Quest, Event, Turn, Asset.
- Перейти с in-memory store на SQLite, SQLAlchemy 2 и Alembic.
- Добавить загрузку/сохранение кампаний и резервные копии.
**Готово, когда:** перезапуск backend не теряет кампании.

## Этап 4. Универсальный Game Engine
- Вынести броски, проверки, инвентарь и правила в независимые модули.
- Добавить интерфейс ruleset, проверку предметов, целей и условий квестов.
- Реализовать подтверждённые игровые события.
**Готово, когда:** механики работают одинаково в разных Story Packs.

## Этап 5. NPC memory
- Разделить личность, знания, отношения и эпизодическую память.
- Фиксировать свидетелей событий и источники знаний.
- Передавать LLM только релевантный контекст; начать с SQLite.
**Готово, когда:** NPC не знает неизвестные ему события и помнит важные контакты.

## Этап 6. Медиа
- Asset Manager с ID и метаданными.
- Библиотека портретов/фонов, очередь ComfyUI, Piper TTS и voice profile.
- Кэширование; не запускать тяжёлую генерацию параллельно с LLM на 8 GB GPU.

## Этап 7. Визуальная новелла
- Фон/персонажи, диалоги, лист персонажа, инвентарь, журнал, квесты, карта и бой.

## Этап 8. Проверка универсальности
- Создать второй Story Pack (например sci-fi или horror).
- Запустить две истории на одном движке и системе сохранений.
**Главный критерий платформенного ядра:** две разные истории работают на общем движке, с отдельным контентом и сохранениями.

## Не делать в первом релизе
- Не строить микросервисы, мультиплеер и облачный backend.
- Не внедрять Qdrant до реальной необходимости.
- Не запускать тяжёлые GPU-модели одновременно.
- Не создавать редактор Story Pack до стабилизации формата.
- Не переписывать проект целиком одним большим изменением.
