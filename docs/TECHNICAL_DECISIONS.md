# Технические решения (ADR-lite)

Этот файл фиксирует решения, которые должны оставаться согласованными во время разработки. Решения можно пересматривать, но изменение должно быть осознанным.

## TD-001. Модульный монолит вместо микросервисов

**Решение:** один FastAPI backend с внутренними доменными модулями.

**Причина:** проект локальный, одиночный, команда разработки небольшая. Микросервисы добавят инфраструктурную сложность без пользы на текущем этапе.

## TD-002. Story Pack отделён от Game Engine

**Решение:** сеттинг, лор, NPC, локации, предметы и квестовые данные живут в пакетах историй. Общие правила и механики — в движке.

**Причина:** одна платформа должна поддерживать много жанров и миров.

## TD-003. Game Engine — единственный источник механической истины

**Решение:** LLM не меняет напрямую HP, характеристики, предметы, квесты и состояние мира. Она возвращает структурированное предложение; backend валидирует и исполняет его.

**Причина:** устранить выдуманные предметы, неподтверждённое применение предметов, произвольные изменения характеристик и сюжетные противоречия.

## TD-004. Local-first

**Решение:** модели, сохранения и ассеты хранятся локально. Внешний сервер не обязателен для игры.

## TD-005. SQLite сначала

**Решение:** начать с SQLite, SQLAlchemy 2 и Alembic. PostgreSQL рассматривать только при появлении реальной потребности.

## TD-006. Asset ID вместо путей от LLM

**Решение:** AI выбирает идентификатор ресурса из доступного набора. Media Manager разрешает ID в локальный файл.

**Причина:** безопасность, повторное использование и визуальная согласованность.

## TD-007. GPU-задачи выполняются через очередь

**Решение:** не запускать тяжёлую генерацию изображений одновременно с LLM на RTX 3070 8 GB. TTS на первом этапе использовать CPU-вариант.

## TD-008. Сначала структурированная память

**Решение:** память NPC хранить в SQLite и извлекать по сущностям/тегам. Векторную БД добавлять только при доказанной необходимости.

## TD-009. Миграция без переписывания с нуля

**Решение:** перед каждым изменением изучать существующий код, сохранять работающие части и добавлять тесты. Архитектурная целевая структура не означает немедленного переименования всех файлов.
